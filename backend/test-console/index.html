Hospital Follow-up API Test Console

Small development UI for exercising the backend workflow. Requests go to this server; the page does not store your bearer token after you close it.

Not signed in
Development only. Use synthetic records. The local form template is intentionally unconfigured and outbound messaging is disabled.

1. Service and demo login

Development tokens expire after 15 minutes. Switch accounts to exercise role-specific endpoints.

Open API docs 
Sign in to see the current user and permissions.

2. Create synthetic patient and encounter

Use the doctor account to create these records. The clinician ID is filled from the doctor account when available.

Created record details appear here.

3. Upload and process a scan

Upload a JPEG, PNG, or WebP. Processing needs a configured fixed-layout form template; otherwise the scan fails closed.

Scan responses appear here.

4. Record clinician decision

Sign in as doctor. The doctor records the clinical choice before assistant verification.

Decision response appears here.

5. Verify scan as assistant

Sign in as assistant_verifier. Confirm the identifiers match the patient and encounter records above.

Verification response appears here.

6. Policies

Policy approval and activation require the supervisor account and an explicit approval reference.

Policy responses appear here.

7. Follow-ups and reminder queue

Use assistant, doctor, coordinator, supervisor, or auditor accounts according to the endpoint permissions.

Follow-up and reminder responses appear here.
